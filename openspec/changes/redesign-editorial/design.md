## Context

動機見 proposal.md。目前網站是 `add-showcase-mvp` 的「鉤織花邊」版本（該 change design 的 D12 / D14 / D15），樣式集中在一份約 1,000 行的 `wwwroot/css/site.css`，互動在約 80 行的 `wwwroot/js/site.js`。核准的樣稿是三個靜態 HTML（首頁、資料齊全的商品頁、資料未填的商品頁），放在 repo 外的 `D:\jenjenknits\design-mockups\`（`a-editorial.*`、`a-product-*.html`）；作品列表頁沒有樣稿，照同一套元件設計。

限制：
- 不改商品資料格式與路由，現有商品資料夾不需調整
- 商品資料多數未填（例如網格托特包沒有價格、材質、尺寸、故事），版面要在欄位缺漏時仍成立
- 使用者重視手機實際使用體驗，不只是「沒有水平捲軸」

## Goals / Non-Goals

**Goals:**
- 首頁、作品列表、商品頁、404／錯誤頁全部換成「編織誌」視覺，元件共用
- 樣稿的手機行為一起落地：照片滿版滑動、縮圖橫向捲動、模擬器預覽固定在上方
- 移除不再使用的 CSS 與 JS，不留兩套樣式並存

**Non-Goals:**
- 不新增 `meta.json` 欄位（例如照片圖說）
- 不改商品掃描、排序、購買按鈕切換規則
- 不做深色模式（品牌是紙本印刷感，維持單一淺色）

## Decisions

### D1. 視覺系統：紙張、墨色、藏青單色點綴

- 顏色：紙張 `#F4F0E8`、卡片 `#FBF9F4`、墨色 `#16140F`、次要文字 `#5E584E`、細線 `rgba(22,20,15,.22)`、點綴藏青 `#1F3C8E`（只用在編號、圖號、目前狀態）
- 字體：Noto Serif TC 400/600/900（中文）、Instrument Serif（數字、價格、英文 logo）、IBM Plex Mono（小標、圖號）
- 印刷語彙：照片四角裁切線、`Fig. 01` 圖號、雙線分隔、章節大編號 `01`

**替代方案**：第二輪的 D「拆線」、E「收據」、F「曬衣繩」概念更強，但手機上的使用負擔大（例如 D 首屏要捲 3.3 個螢幕）；第一輪的 B、C 太接近原本的版面。A 的資訊比例最接近使用者想要的。

### D2. 紙張顆粒放在背景，不疊在照片上

樣稿用一層蓋滿全頁的 `mix-blend-mode: multiply` 顆粒。實作改成 `body` 的 `background-image`（同一張 SVG 雜訊），只出現在紙張底色上。

**理由**：照片顏色要準（客製顏色是賣點）；整頁混合圖層在低階手機捲動時成本高。

### D3. 22 色印刷色條取代首頁色點互動

刊頭下方一排 22 格色條，由 `_Layout` 從 `YarnPalette` 伺服器端產生，純裝飾（`aria-hidden`），不需要 JS。原本首頁的「滑過色點換標題顏色」移除。

**理由**：色條在每一頁都出現，比只在首頁的互動更像品牌識別；少一段 JS。

### D4. 首頁：第一屏 + 精選跨頁 + 購買方式

- 第一屏：主照片、直排「貞心卉織」、一句話簡介、看作品按鈕、目錄（`01 作品`、`02 購買方式`，頁碼為裝飾）。主照片是品牌素材，沿用 `images/hero/puff-flower-lake.jpg` 寫在頁面上
- 精選跨頁（資料來源見 D5），奇數件照片在左、偶數件照片在右
- 購買方式沿用 `IsOnSale` 文案切換，三個步驟改為大號中文數字
- 「關於」整段移除

### D5. 跨頁與商品頁的照片、圖號規則

- 跨頁主照片 = `cover.*`；下方小圖 = gallery 前 4 張（不足就少放，沒有就不顯示小圖列）
- 編號 `No. 01` = 在精選中的順序；`Fig.` 圖號在同一頁內連續編號
- 規格表只列有值的欄位（價格、材質、尺寸），全部沒有就不顯示整個表
- 圖說：`meta.json` 沒有圖說欄位，所以只顯示圖號與商品名稱，不像樣稿那樣逐張描述

**替代方案**：新增 `captions` 欄位讓每張照片有描述，但目前沒有內容來源，且會增加上架負擔，等有需要再加。

### D6. 商品頁章節化

- 上半部：照片輪播（左）+ 資訊欄（右，桌機 `position: sticky`）
- 章節依有無資料動態編號：有故事時「01 故事」；有色卡或模擬器時「可選顏色」接在後面（沒有故事時它就是 01）
- 故事第一段首字放大；故事旁配圖用 gallery 最後一張（通常是情境照），沒有 gallery 時故事全寬
- 資訊欄的「挑配色 ↓」只在有可選顏色章節時出現

### D7. 配色模擬器：先選部位，再點色票

原本是兩組各 22 個 radio（主色、配色各一組），手機上很長。改成：
- 兩個「部位」鈕（主色／配色），同時顯示目前色號與色塊，`aria-pressed` 標示正在改哪一個；整組 `aria-live="polite"` 讀出色號變化
- 一組 22 張色票按鈕，標示目前部位的選擇，並以「主」「配」標籤標出兩個已選顏色
- 手機版預覽（小花 + 兩個部位鈕）縮成一條，`position: sticky` 固定在模擬器區塊頂端

小花 SVG 幾何沿用現有 partial；預設維持 12 號配 6 號。

### D8. 下一件作品

`DetailModel` 從 `GetAll()` 的順序取目前商品的下一件，最後一件之後接回第一件；只有一件商品時為 `null`，頁面不顯示該區塊。

### D9. 保留的行為

- 換頁轉場：作品卡片照片與商品頁第一張照片共用 `view-transition-name`
- 作品卡片滑過換成第一張 gallery（只在有滑鼠的裝置載入與顯示）
- skip link、`:focus-visible`、按鈕至少 44×44px、`prefers-reduced-motion`
- 刊頭在換頁時不參與轉場（`view-transition-name: site-header`）

### D10. 整份改寫 `site.css`

不在舊樣式上疊新樣式，直接改寫整份檔案，沿用既有寫法（行動優先、`min-width` 斷點、一行一個屬性、註解寫原因）。舊的色帶、扇形花邊、花朵遮罩、色點、卡片錯落等 class 一併刪除。

## Risks / Trade-offs

- [襯線中文長文在小螢幕較難讀] → 內文 16–17px、行高 1.9；故事欄寬限制在約 36 字
- [Noto Serif TC 字檔大] → Google Fonts 依 unicode-range 分片載入、`display=swap`；第一屏只有少量字
- [資料未填的商品頁顯得單薄] → 版面在缺欄位時仍完整（樣稿已驗證網格托特包），補資料即改善
- [直排大標在極窄螢幕擠壓照片] → 手機上大標縮到約 15vw，照片與大標並排；320px 寬時再驗證一次

## Migration Plan

1. 在 `redesign-editorial` 分支實作，`dotnet build` 與手機／桌機截圖驗證通過後再合併
2. 不涉及資料遷移；回滾 = revert 合併 commit
3. OpenSpec 歸檔順序：先 `add-showcase-mvp`，再本 change

### D11. 動態原則（2026-10-07 新增，依 impeccable animate 規則檢查後修訂）

- 只有首頁有一段開場，概念是「油墨印上去」：色條一格格印出、直排標題由上往下印出、最後蓋上印章，總長約 1 秒；其他頁面換頁時沒有開場動畫（色條只在首頁播放，`body.is-home`）
- 其餘動態只用在回饋、狀態變化與換頁連續感：換頁轉場、模擬器換色、照片輪播、卡片滑過換照片（250ms）
- 拿掉裝飾性的滑過放大（跨頁主照片、小圖）與色票浮起；色票滑過只描邊，浮起留給「選中」
- 減少動態效果：拿掉開場動畫與位移，保留 150ms 的顏色與透明度變化，讓操作回饋仍看得出來
